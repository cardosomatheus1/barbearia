# R12 · Usabilidade cronometrada e operação assistida

R12 não é teste de código. É a resposta empírica para a pergunta que motivou a
reorganização: **uma pessoa nova consegue entender o Barberdock sem treinamento?**

## O que não pode ser reconstruído

A linha de base anterior a V1/V5/V11 não foi cronometrada antes das mudanças.
Ela está perdida. Os ZIPs antigos preservam interface, mas colocar hoje uma
pessoa numa versão antiga e chamar isso de “o antes” já muda contexto, dados e
ambiente; inventar segundos seria pior. O repositório registra essa ausência em
vez de preencher a tabela com estimativa.

O primeiro checkpoint válido passa a ser **pós-reorganização**. A partir dele,
toda mudança relevante pode ser comparada com uma medição real anterior.

## Cinco tarefas

A pessoa começa autenticada, numa barbearia de demonstração com João Silva,
agendamentos e caixa semeados. Não recebe explicação da estrutura do menu.

1. **Encontre o cadastro do João Silva.**
2. **Agende o João para amanhã.**
3. **Veja quanto o João está devendo.**
4. **Veja quem é o próximo cliente a ser atendido.**
5. **Veja quanto a casa faturou hoje.**

O cronômetro começa quando a tarefa é lida e para quando a pessoa diz que
terminou. Se ela desistir, registra-se falha e o tempo até a desistência. Ajuda
do moderador invalida aquela tentativa; a nota explica por quê.

## Quem participa

- pessoa que nunca abriu o Barberdock;
- papel registrado: recepção, barbeiro, gerente ou dono;
- identificador anônimo (`P01`, `P02`), nunca nome/telefone;
- ideal: pelo menos 5 pessoas na primeira rodada, vindas de 3–5 barbearias.

Não se mistura papel em tarefa sem permissão. A tarefa 5, por exemplo, precisa
de um perfil que possa ver faturamento.

## Como registrar

```bash
node scripts/r12-usabilidade.mjs sessao \
  --checkpoint pos-reorganizacao \
  --participante P01 \
  --papel recepcao
```

O script conduz as cinco tarefas e grava JSON em `medicoes/r12/`. Esses arquivos
ficam fora do Git por padrão, porque são observação de campo. Para resumir:

```bash
node scripts/r12-usabilidade.mjs resumo
```

O relatório usa **mediana**, taxa de conclusão e faixa mínima–máxima por tarefa.
Média sozinha é ruim aqui: uma pessoa perdida por quatro minutos arrasta o
número inteiro e esconde que as outras quatro acharam em seis segundos.

## Operação assistida em paralelo

Cronômetro de laboratório não substitui turno real. Em 3–5 casas, registrar ao
menos estes três momentos:

- recepção num horário de pico (ex.: sábado 11h): chegada, fila, remarcação e caixa;
- barbeiro fechando atendimento/comanda;
- dono conferindo faturamento/resultado no fim do dia.

Para cada ocorrência anotar: **o que a pessoa queria fazer · onde hesitou · se
pediu ajuda · o que esperava encontrar · resultado**. Não se corrige na hora
para “salvar o teste”; primeiro registra-se o atrito, depois se ajuda a operação.

## Critério de leitura

R12 não cria meta arbitrária de “5 segundos”. Compara o produto consigo mesmo.
O sinal de melhora é: mediana menor, taxa de conclusão maior e menos pedidos de
ajuda, sem sacrificar permissões ou esconder função necessária.
